# 项目范围：做什么，不做什么

DSH Tavern 已进入稳定阶段。接下来的重心是**维护人物卡的可玩性**：让现有的人物卡，在现有的游玩流程里跑得更好。不盲目扩张功能；新功能只在维护可玩性所必需时才做。

提需求前请先看这份清单。清单里的方向不是“暂时没空”，而是有意不做：每多一个方向，维护成本和出错的组合就多一层，最终伤害的是已有功能的稳定。

## 做

- **人物卡兼容**：卡在原版酒馆能用、在这里不能用，就是我们的问题。我们改程序适配卡，不要求卡作者改卡。
- **稳定性**：安装、更新、回滚，以及桌面、命令行、安卓三端行为一致。
- **性能**：长对话、存档体积、启动与响应速度。
- **可诊断性**：出错时说清是哪一步、为什么失败，一次就能定位。
- **安装与更新体验**：少步骤、少等待、失败可恢复。
- **逐步开放插件接口**：清单里不内置的功能，尽量开放稳定的[插件接口](https://github.com/flizzywine/dsh-tavern/wiki/%E6%8F%92%E4%BB%B6%E5%BC%80%E5%8F%91%EF%BC%9A%E6%8E%A5%E5%8F%A3%E6%80%BB%E8%A7%88)，让需要的人自己做成插件。接口先开放「添加」类（提示词段落、世界书条目、结算工具、媒体等）；「替换」类（由插件接管某个流程）也可以开放，但必须约定插件要交回什么，并且插件失败时自动退回 Tavern 自己的做法。接口带版本号、只加不改。缺接口请提[插件接口需求](https://github.com/flizzywine/dsh-tavern/issues/new?template=plugin-api.yml)。

判断标准：**它是否让“现有的卡在现有的流程里跑得更好”？** 是就考虑，否则默认不做。

## 插件：吸收我们想不到的东西

该做什么功能、做成什么样，信息分散在每个玩家和卡作者手里，没有谁能全部知道。插件接口是让这些巧思流进来的渠道：做得好的插件可能被精简后吸收进本体，或者只吸收它的思路；吸收时署名原作者，接口不变，原插件照常可用。拿不准值不值得做的需求，我们更愿意先开接口，让需要的人做出来看看。详见[插件生态](plugin-ecosystem.md)。

## 不做

### 换赛道的

| 不做 | 原因 |
| --- | --- |
| 群聊、多角色同场 | 上下文、发言轮次和结算都要重做，等于另一个产品。 |
| 写小说、长篇创作模式 | 已有专门的写作工具；这里专注角色扮演。 |
| 通用的酒馆插件兼容 | 等于再造一个 SillyTavern。已支持的酒馆助手、MVU、提示词模板（EJS）、正则、状态栏与前端卡到此为止。 |
| 其他前端的卡片和存档格式（Risu、Agnai 等） | 只认 SillyTavern 人物卡。 |
| 语音朗读、语音输入、视频或动图生成 | 多媒体不是文字游玩的核心。交给第三方 DSH 插件，通过[插件接口](https://github.com/flizzywine/dsh-tavern/wiki/%E6%8F%92%E4%BB%B6%E5%BC%80%E5%8F%91%EF%BC%9A%E6%8E%A5%E5%8F%A3%E6%80%BB%E8%A7%88)挂到正文里。 |

### 做平台的

| 不做 | 原因 |
| --- | --- |
| 账号、云同步、多用户 | 数据始终只在你自己的设备上。 |
| 卡片市场、社区分享、在线排行 | 内容分发不是本项目的职责。 |
| iOS、Mac 安装包、Linux 桌面版等新平台 | 维持现有的 Windows 安装包、命令行与安卓三端。 |
| 跟进每个新版 DSH | 固定在已适配的 DSH 版本（当前 0.1.5-rc.2）。等 DSH 真正稳定后，再集中适配一次。 |

### 做了停不下来的

| 不做 | 原因 |
| --- | --- |
| 接入更多生图服务、ComfyUI 工作流编辑、内置生图的新能力 | 内置生图只做小改进，不加新能力。新的生图方式请做成插件，见[插件接口](https://github.com/flizzywine/dsh-tavern/wiki/%E6%8F%92%E4%BB%B6%E5%BC%80%E5%8F%91%EF%BC%9A%E6%8E%A5%E5%8F%A3%E6%80%BB%E8%A7%88)。 |
| 主题或皮肤编辑器、自定义界面布局 | 外观维持现有皮肤。 |
| 世界书与预设的高级可视化编辑 | 能导入、能做基本编辑即可；复杂编辑请用专门工具。 |
| 玩法系统（成就、好感度、背包、地图等） | 这些属于人物卡自己；我们负责把卡跑对。 |
| 新的记忆或总结算法试验 | 维持现有机制，只修问题。 |
| 联网搜索以外的新工具（代码执行、文件操作等） | 工具越多，前台越容易跑偏。 |
| 界面多语言 | 用户以中文为主，翻译维护是长期成本。 |

## 那我遇到问题怎么办

- **某张卡在原版酒馆正常、在这里不正常**：这正是我们要修的，请附上人物卡文件和日志反馈。
- **想要清单里的功能**：可以在 [Discord 交流群](https://discord.gg/hYAEjKnpra)交流，或寻找、编写对应的 DSH 插件。本项目不会照需求内置，但做得好的插件可能被吸收，见[插件：吸收我们想不到的东西](#插件吸收我们想不到的东西)。
